# 予約可能状況チェック（ビジネスホテルしらさぎ）

## 目的

毎月1日に、**公式HP（tripla）と全OTA** で「本日〜3ヶ月先の月末」までの各日が
予約できる状態か確認する。主な狙いは **在庫の登録漏れ・販売停止・プラン期限切れ** の発見。
（例：11月1日実行 → 11月1日〜翌年2月末日までを確認。特に新しく3ヶ月先になった月を重点確認）

## 確認先

確認先の URL は [sites.md](sites.md) にまとめてある。サイトが増減したらそちらを更新する。

## 手順

1. **対象期間を決める**: 実行日（日本時間）から、3ヶ月後の月の末日まで。
2. **各サイトを順に確認する**。使うブラウザは次の優先順:
   1. **Claude in Chrome**（`mcp__claude-in-chrome__*` ツール。無ければ ToolSearch で `claude-in-chrome` を検索し、
      `enable__mcp__claude-in-chrome` があれば先に呼ぶ）。オーナーのパソコンの Chrome で開くので、
      クラウドからは 403 で弾かれる **公式HP（tripla）と JTB もこちらなら確認できる**。
      最初に `tabs_context_mcp` を呼び、新しいタブを開いて作業し、終わったら自分で開いたタブを閉じる。
      サイトの許可を求められたらオーナーに許可を依頼して待つ。
   2. Chrome が使えない（クラウド実行など）ときは Playwright + 事前インストール済みの Chromium
      （`executablePath: '/opt/pw-browsers/chromium'`。`playwright install` は実行しない）。
      この場合、公式HPと JTB は 403 になりやすいので ❓ として記録し、
      「パソコンの Claude デスクトップアプリ（Chrome 接続）で再確認が必要」とレポートに書く。
   - 条件は **大人1名・1泊・1室**（sites.md に別条件があればそれも）。
   - 月表示の空室カレンダーがあるサイトはカレンダーで月ごとに確認する
     （○/△/×/残室数/「-」「販売なし」の区別を記録）。
   - カレンダーがないサイトは、各週の代表日（月・金・土）と各月の1日・15日・末日を個別に検索する。
   - 各サイトでスクリーンショットを `reports/availability/YYYY-MM/` に保存する。
3. **判定する**（日付 × サイトごと）
   - ✅ 予約可能（空室あり・プラン表示あり）
   - ⚠️ 満室（在庫0。繁忙日なら正常の可能性あり）
   - ❌ 販売なし（プラン未設定・期間外・在庫未登録・「予約受付前」など）← **最重要の要対応**
   - ❓ 確認できず（サイトエラー・ブロック・ログイン要求など。理由を書く）
4. **サイト間の差異を見る**: 公式HPでは予約可能なのに OTA だけ販売なし（またはその逆）の日は
   在庫配分・サイトコントローラー連携の漏れの可能性が高いので強調する。
5. **レポートを書く**: `reports/availability/YYYY-MM.md` に以下の形式で保存する。

   ```markdown
   # 予約可能状況レポート YYYY年MM月DD日実行
   対象期間: YYYY-MM-DD 〜 YYYY-MM-DD / 条件: 大人1名・1泊・1室

   ## 要対応（❌販売なし・サイト間の差異）
   - 2027-02-01〜02-28 じゃらん: 全プラン販売なし（プラン掲載期間が1月末で終了している可能性）

   ## サイト別サマリー
   | サイト | 月 | ✅ | ⚠️ | ❌ | ❓ | 備考 |

   ## 確認できなかった項目
   ```
6. **コミットしてプッシュする**（レポートとスクリーンショット）。
7. **最終返信**は「要対応」の内容を先頭に、短く日本語でまとめる。問題がなければ「全サイト予約可能」と明記する。

## 注意

- 予約・仮押さえ・会員ログインは**絶対にしない**。閲覧と検索のみ。
- サイトにアクセスできない場合（ネットワーク制限・ボット対策など）は ❓ とし、
  推測や架空の結果で埋めない。どのホストが失敗したかをレポートに書く。
- 料金は参考として記録してよいが、判定は「予約できるかどうか」で行う。
